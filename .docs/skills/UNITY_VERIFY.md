# Unity 변경 검증

코드·씬·에셋을 변경했거나 커밋·PR 전에 검증을 요청했을 때 사용한다. 변경 범위에 비례해 실행하고, 실행하지 못한 검증은 이유를 명시한다.

## 공통 점검

1. `git diff --check`로 공백 오류를 확인한다.
2. `git status --short`로 생성물과 의도하지 않은 파일이 없는지 확인한다.
3. `Assets/`의 추가·이동·삭제 원본마다 `.meta` 파일이 함께 처리됐는지 확인한다.
4. 변경된 씬 이름과 `SceneNames` 상수, Build Settings 등록 여부를 필요한 범위에서 대조한다.

## 코드 및 테스트

- C# 코드가 바뀌면 Unity Editor Console에서 컴파일 오류가 없는지 확인한다.
- 테스트가 있거나 새 테스트를 작성했다면 Unity Test Framework의 EditMode·PlayMode 중 관련 범위를 실행한다.
- Unity Editor를 배치 모드로 실행할 수 있는 환경이면, 사용한 Unity 버전과 정확한 명령을 결과에 남긴다.

## 플레이 확인

- 플레이어 조작 변경: 이동, 점프, 달리기, 스태미나 회복·소모, 회피를 확인한다.
- 프롤로그 변경: 관련 프롤로그 씬의 진입, 전환, 종료 흐름을 확인한다.
- 입력 변경: 연결된 Action Map과 실제 디바이스 입력을 확인한다.

## 결과 형식

```text
검증 결과
- 통과: <검사 또는 테스트>
- 미실행: <검사와 사유>
- 남은 위험: <없음 또는 구체적 내용>
```
